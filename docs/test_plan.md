# План тестирования

## 1. Цели и задачи тестирования

**Цель:** убедиться, что функции вычисления площади и периметра прямоугольника и треугольника возвращают корректные результаты.

**Задачи:**
- определить наборы входных данных и вручную рассчитать ожидаемые результаты;
- реализовать автоматические unit-тесты с использованием модуля `unittest`;
- выполнить ручное тестирование и сопоставить фактические результаты с ожидаемыми;
- зафиксировать результаты и выявленные дефекты (при наличии).

## 2. Описание тестируемого продукта

Программный проект на Python для геометрических расчётов. Реализованы четыре функции:

| Модуль | Функция | Назначение |
|--------|---------|------------|
| rectangle.py | `area(a, b)` | площадь прямоугольника по двум сторонам |
| rectangle.py | `perimeter(a, b)` | периметр прямоугольника по двум сторонам |
| triangle.py | `area(a, h)` | площадь треугольника по стороне и высоте к ней |
| triangle.py | `perimeter(a, b, c)` | периметр треугольника по трём сторонам |

Требования: функции принимают числа (целые или дробные) и возвращают число, вычисленное по соответствующей формуле.

## 3. Область тестирования

**В области тестирования:**
- функции `area` и `perimeter` модуля `rectangle`;
- функции `area` и `perimeter` модуля `triangle`;
- корректность результата на целых и дробных числах, на нулевых значениях и частных случаях фигур.

**Вне области тестирования:**
- проверка входных данных (отрицательные значения, нечисловые типы, существование треугольника по трём сторонам), так как в продукте такая логика не реализована;
- производительность и безопасность.

## 4. Стратегия тестирования

- **Тип тестирования:** функциональное, методом чёрного ящика (проверяется результат функции при заданных входных данных).
- **Уровень:** модульное (unit) тестирование.
- **Инструмент:** стандартный модуль `unittest` языка Python; тесты оформлены в классах, унаследованных от `unittest.TestCase`, имена тестовых методов начинаются с `test`, проверки выполняются через `assertEqual` и `assertAlmostEqual`.
- **Техники подбора данных:** граничные значения (ноль), эквивалентные классы (целые, дробные), частные случаи (квадрат, равносторонний и прямоугольный треугольник), проверка свойства независимости результата от порядка аргументов.
- **Ручное тестирование:** расчёт ожидаемого результата по формуле, запуск функции с теми же данными, сравнение результатов (таблица в п. 5).
- **Запуск:** `python -m unittest -v test_rectangle.py test_triangle.py`.
- **Хранение:** исходный код тестов размещён в репозитории GitHub, факт появления тестов отражён в `docs/history.md`.

## 6. Критерии приемки

Тестирование считается успешно завершённым, а продукт принятым, если:
- все 19 unit-тестов завершаются со статусом `OK`;
- все ручные тест-кейсы имеют статус Passed;
- отсутствуют критические дефекты в области тестирования;
- исходный код тестов размещён в репозитории, а факт появления тестов отражён в истории проекта.

## 7. Ожидаемые результаты

- вывод `unittest` с итогом `Ran 19 tests ... OK`;
- заполненная таблица ручных тест-кейсов (п. 5) со статусами выполнения;
- скриншоты успешного запуска тестов и запуска с ошибкой;
- перечень выявленных дефектов и ограничений: функции не проверяют входные данные (отрицательные значения, невозможные наборы сторон треугольника), рекомендуется добавить валидацию с выбрасыванием `ValueError`;
- метрики качества: 19 из 19 тестов пройдено (100 %), 16 из 16 ручных тест-кейсов пройдено (100 %).
